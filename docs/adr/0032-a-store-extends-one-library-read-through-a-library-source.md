# ADR-0032: A store extends one library, read through a library source

Each store extends exactly one media library, read through a library source whose records are in the store's own vocabulary — items with their kind, title, year, duration, external ids, tags, people, studio and files; plays; signal types and signals — never a library's own JSON. Plex is the built-in library source and the default; any other library is read by a Rhai script the writer loads at runtime from a folder outside every checkout, which reaches only the host functions the writer registers (an HTTP JSON call, the environment variables the configuration lists, a log line, and sinks for items, plays, signal types and signals), and whose every record the writer validates at that boundary, failing the walk with the script's file and line on any error. The library source is the store's only required dependency, a second library is a second store, and a consumer asks the library source directly for anything it can answer.

The store holds facts about the items its library source lists and the extras a person declared ([ADR-0030](./0030-an-extras-library-is-a-declared-folder-the-writer-walks-and-a-person-organizes)) — windows inside them, plays, published groupings, a person's decisions, signals, and its own fetch bookkeeping — and a signal alone may name a performer, studio or tag, by the source's own id, instead of an item.

Each library source declares its external-id namespaces in priority order, and [ADR-0002](./0002-item-id-is-first-hit-wins-over-external-guids)'s first-hit-wins rule runs over them: Plex's stays `imdb` → `tmdb` → `tvdb` → `plex`, else `fs:<hash>`; Stash's is `stashdb` → `fs:<hash>`.
