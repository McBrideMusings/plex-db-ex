# ADR-0028: List decisions and fetch attempts are keyed by list URL, in tables beside the facts

A person's decision about a crowd list lives in `list_decision`, and a failing list's fetch bookkeeping in `list_attempt`; both are keyed by the list's canonical URL. Neither is an `enrichment_cursor` row: that table is keyed by `items(item_id)`, and a list is not an item (ADR-0023). A list that was added or has failed may have no `collection` row yet, and no `collection_id` either, so the URL is the only key that exists for it and the one a person types. `list_decision.added` keeps the fact that a person added a list, because `list_decisions.json` holds one entry per URL and a later `refetch` replaces the `added` entry. Both tables are bookkeeping, never facts (ADR-0013), and only the fold and the harvest write them.
